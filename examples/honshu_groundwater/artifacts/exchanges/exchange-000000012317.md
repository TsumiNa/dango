# Reasoning

The task is feasible and within this skill’s scope, but the current planner draft is too generic. This skill does not do arbitrary “data processing and reporting”; it runs a specific training script that fits a spatial Gaussian-process model from enriched groundwater observations, writes prediction outputs to CSV, and writes a surface visualization to SVG. Readiness depends mainly on whether the upstream data already includes the required normalized spatial and groundwater fields.

Revised execution approach for orchestrator review:

   - Confirm the upstream enriched observations include the exact required fields:
     - `latitude`
     - `longitude`
     - `elevation_m`
     - `water_level_m_bgl`
   - If `elevation_m` is missing, stop and route through an upstream elevation enrichment step first.

2. **Use the canonical execution path**
   - Run `scripts/train.py` from the skill source workspace.
   - Pass the upstream exchange markdown body verbatim so the script can extract the upstream JSON block itself.
   - The script fits a `scikit-learn` `GaussianProcessRegressor` using an `RBF + WhiteKernel`.

3. **Expected outputs**
   - Save groundwater prediction outputs as **CSV** for downstream analysis.
   - If prediction is produced on a reproducible Honshu grid or surface, that prediction table should be the CSV artifact.
   - Save the model surface plot as **SVG** via `matplotlib` if produced by the script.
   - Do **not** create any PDF.

4. **Assumptions and limitations to report in execution handoff**
   - This is a **spatial statistical interpolator**, not a physical groundwater flow model.
   - Mixed source notation has been normalized upstream into `water_level_m_bgl`.
   - Prediction quality is limited by sparse and uneven observation coverage across Honshu.
   - Estimated vs direct observations are handled only to the extent supported by the upstream data and existing script behavior.
   - Elevation is a key predictor; weak or missing elevation enrichment materially reduces model quality.

5. **Execution note**
   - During execution, use the one canonical script invocation rather than custom glue code.
   - The eventual handoff should include the script-produced artifact paths, especially the CSV prediction path(s) and any SVG plot path.

In plain terms: this task is in scope and ready to execute once the upstream exchange is confirmed to include `latitude`, `longitude`, `elevation_m`, and `water_level_m_bgl`. If elevation is missing, perform upstream elevation enrichment first.
